CS-210 Corner Grocer – Algorithms & Data Structures Artifact

Overview

This artifact is based on my original CS-210: Corner Grocer project, which reads a list of grocery items, calculates purchase frequencies, and displays the results to the user. For my CS-499 Capstone, I enhanced this project to demonstrate proficiency with algorithms, data structures, and efficient problem-solving. The enhanced version focuses on improving performance, organizing the logic more clearly, and adding functionality that would be useful in a real grocery analytics scenario.

Original Artifact (Before Enhancement)

In the original CS-210 implementation, the program:

  • Read items from an input file and counted occurrences
  • Used basic containers and loops to manage item frequencies
  • Displayed counts to the console and generated a simple text file
  • Provided a basic histogram-like output but with limited flexibility

While this version met the course requirements, it did not fully leverage more advanced data structures or algorithmic patterns that could make the solution more scalable and extensible. This made it a strong candidate for enhancement in the Algorithms & Data Structures category.

Final Enhanced Artifact — CS-499 Submission

For the capstone, I refactored and extended the Corner Grocer program to use more efficient data structures and to support additional analytics-style features. The enhanced version includes the following improvements:

  • unordered_map for O(1) lookups — Replaced less efficient structures with std::unordered_map to store item frequencies, providing average constant-time access and updates.
  • Min-heap for Top-K frequent items — Added a std::priority_queue (min-heap pattern) to compute the most frequently purchased items without sorting the entire dataset each time.
  • Trie (prefix tree) for prefix searches — Implemented a Trie structure to support fast prefix-based search, allowing users to look up all items that start with a given prefix (for example, items starting with “ap”).
  • Input normalization and validation — Normalized case and spacing for consistent lookups and added checks for invalid or empty input to improve robustness.
  • Improved code structure and readability — Separated logic into functions, reduced duplication, and added comments to make the program easier to understand and extend.

These enhancements transform the program from a straightforward frequency counter into a more flexible analysis tool showcasing the practical use of data structures in solving real problems.

CS-499 Outcomes Demonstrated

Outcome 1 — Design and Evaluate Computing Solutions:
By selecting appropriate data structures (unordered_map, priority queue, Trie) and analyzing their performance characteristics, I designed a more efficient solution for counting, searching, and ranking items. This demonstrates an understanding of algorithmic trade-offs and how they affect runtime and scalability.

Outcome 3 — Algorithms and Data Structures:
The enhanced artifact directly focuses on using algorithms and data structures to solve a real problem. It shows how hash-based maps, heaps, and Tries can work together to support lookup, aggregation, and query features in a single application.

Outcome 4 — Use of Appropriate Tools and Techniques:
I applied modern C++ standard library containers and patterns rather than writing everything from scratch, mirroring how a professional developer would rely on tested, well-supported abstractions.

Reflection

Enhancing the Corner Grocer project helped me deepen my understanding of how data structures directly impact the performance and capabilities of an application. Moving from simple loops and basic containers to unordered maps, heaps, and Tries showed me the value of choosing the right structure for the right task. I also learned how important it is to keep code organized and well-documented so that features like “Top-K items” or “search by prefix” can be added cleanly in the future.

Overall, this artifact now represents my ability to think algorithmically, reason about complexity, and implement efficient data-driven solutions — skills that are critical for both software engineering and full-stack development roles.
