CS-360 Event Tracker — Android App Artifact (Software Design & Engineering)

Overview

The Event Tracker application was originally created in CS-360: Mobile Architecture and Programming. It allowed users to create and manage simple event entries inside a basic Android interface. For my CS-499 Computer Science Capstone, I selected this project as my Software Design & Engineering artifact because it clearly demonstrates how I can transform an academic prototype into a professionally structured, maintainable application. I enhanced the original project and then produced a final version containing ample comments for clarity and long-term maintainability.

Original Artifact (Before Enhancement)

The original app was built using early Android development principles:

  • Logic was handled mostly inside Activities
  • Limited separation of concerns
  • Basic UI with simple input fields
  • No architectural layers (no MVVM, Repository, or Room)
  • Minimal documentation and comments
  • Events were stored using simple or temporary approaches

This version worked functionally but was not yet designed for scalability or maintainability.

Final Enhanced Artifact — CS-499 Submission

For CS-499, I redesigned the project to align with professional Android development standards.

  • Introduced MVVM Architecture – Separated UI logic from data and business logic, added a clean ViewModel layer, and improved maintainability and testability.
  • Added Room Database for Persistent Storage – Created Event, EventDao, and EventDatabase to enable local on-device data persistence and remove the need for temporary in-memory storage.
  • Added Repository Layer – Centralized data operations, improved scalability and consistency, and prepared the codebase for future features like API sync.
  • Improved UI/UX – Added RecyclerView with a custom EventAdapter, organized event items in card layouts, and added validation and stable user interactions.
  • Added WorkManager Scaffold – Introduced a background processing structure to demonstrate industry-standard practices.
  • Added Ample Comments – Included file-level headers and method-level Javadoc-style explanations to improve readability and clarity for reviewers.

This version is the official CS-499 artifact submission.

CS-499 Outcomes Demonstrated

Outcome 1 — Design and Evaluate Computing Solutions: Redesigned the app using MVVM, Repository, and Room to create a scalable, maintainable solution.

Outcome 2 — Professional Communication: Added comprehensive comments and clear documentation to communicate design intent and improve readability.

Outcome 4 — Use Appropriate Tools and Techniques: Applied Android frameworks such as Room, LiveData, ViewModel, WorkManager, and RecyclerView to deliver a professional-grade application.

Reflection

Transforming this CS-360 project into a CS-499 artifact helped me understand how proper architecture directly impacts maintainability, reliability, and scalability. The enhanced version resembles a real-world Android application and reflects my growth from student-level coding to professional software engineering practices.
