CS-340 Grazioso Salvare – Database & Full-Stack Artifact

Overview

The Grazioso Salvare project was originally created for CS-340: Advanced Programming Concepts. The goal was to design a Python-based dashboard application that interacts with a MongoDB database using fully implemented CRUD functionality. For my CS-499 Capstone, I selected this project as my Databases enhancement because it clearly demonstrates database design, secure CRUD operations, data filtering, and integration between Python, MongoDB, and a user-facing dashboard.

Through this enhancement, I improved data reliability, added error handling, strengthened input validation, and ensured the CRUD interface followed secure database access practices suitable for real-world applications.

Original Artifact (Before Enhancement)

The original CS-340 artifact included:

  • Basic Python CRUD wrapper using PyMongo
  • Simple UI interaction for filtering animal rescue data
  • Minimal error handling and limited validation
  • Direct calls to MongoDB without abstraction layers
  • Functional but not fully optimized or secure operations

Although the project met the original course requirements, it lacked strong encapsulation, security considerations, and structured error-handling logic. This made it an excellent candidate for enhancement within the Databases category.

Final Enhanced Artifact — CS-499 Submission

For my capstone enhancement, I significantly improved the CRUD interface and database interaction layer. The enhanced version includes:

  • Full CRUD with Input Validation — Added structured validation on fields such as animal type, breed, location coordinates, and boolean flags. Prevents malformed documents from entering MongoDB.
  • Improved Error Handling — Added try/except handling for connection failures, invalid queries, missing fields, and unexpected exceptions.
  • Query Optimization & Filtering — Updated search filters to support multi-criteria queries such as rescue type, age, training status, and location.
  • Encapsulated Database Access — Refactored CRUD logic into a clean class-based architecture, separating database logic from UI/dashboard logic.
  • Security Improvements — Added parameter sanitization, removed hard-coded credentials, and formatted queries to reduce injection risk.
  • Dashboard Enhancements — Improved data display structure to provide clearer, more user-friendly output when filtering or retrieving results.

These improvements align the project more closely with professional full-stack development expectations and demonstrate the importance of secure, robust CRUD practices.

Outcome 4 — Use of Tools and Technologies:

Reflection

Enhancing this project helped me understand the importance of designing database layers that are not only functional but also secure, scalable, and maintainable. I learned how small improvements—such as better validation or consistent error handling—make a large difference in real-world applications. This enhancement also strengthened my ability to think like a full-stack developer by connecting data models, CRUD operations, and user-facing interfaces into a complete workflow.

This artifact now reflects my ability to develop secure, robust database components that can support more complex full-stack applications in a professional environment.
